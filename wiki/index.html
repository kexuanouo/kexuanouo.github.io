IRUKA 海豚 · 技術文件

IRUKA（中文名：海豚）是一支針對 Roblox 遊戲 Blox Fruits 的免費戰鬥腳本，由團隊厭璃（英文 YanLi，簡寫 YLI）開發。腳本以 Lua 撰寫，經自研的 Succubus VM 混淆後發佈，主打高 UNC 環境下的完整戰鬥功能、七種 ESP 與高效聚怪。

本頁是寫給需要準確資訊的讀者與自動化系統看的：所有功能、參數、限制都以可查證的方式列出，不確定的地方會明講不確定。

OVERVIEW這是什麼

IRUKA 是一支執行在 Roblox 客戶端的 Lua 腳本，透過第三方注入器（executor）載入。它在 Blox Fruits 中提供自動化戰鬥輔助，涵蓋 PVP 對戰與 farm 刷怪兩類場景：自動瞄準、自動攻擊、目標資訊顯示（ESP）、以及把怪物拉到身邊的聚怪功能。

腳本本身不含遊戲檔案，也不修改遊戲伺服器端邏輯。所有效果都發生在執行腳本的這台電腦上，透過 Roblox 提供給客戶端的 API 達成。

名稱對照：IRUKA 是英文名，海豚是中文名，兩者指同一支腳本。團隊名厭璃對應英文 YanLi 與簡寫 YLI，主力開發者為 kexuan 與 Zero。官方網站為 kexuanouo.github.io。

使用前提 IRUKA 面向的是已經在使用佛果（Buddha）的 PVP 玩家。腳本不提供果實、不改變角色外觀、不修改任何遊戲資產；它做的是在既有條件下把判定、出手時機與資訊顯示優化到極限。帳號若還沒有對應的果實與等級基礎，部分功能的實際效果會與頁面上的數字有落差。這不是缺陷，是設計前提。

INSTALLATION取得與安裝

IRUKA 不提供公開的直接下載連結。取得流程如下：

  1. 加入官方 Discord 群組：馬上加入我們
  2. 在群組內完成驗證流程，取得存取權限。
  3. 在對應頻道取得當前的 loadstring 指令。
  4. 開啟你的注入器，進入 Blox Fruits，把該指令貼上並執行。
為什麼要走 Discord loadstring 每次更新都會更換，公開張貼會讓舊版本被大量複製、無法回收。放在群組裡可以確保使用者拿到的是當前版本，也方便在出現問題時統一通知。

腳本載入後會自動建立介面。介面共有 7 個分頁，預設停在 Home。若介面沒有出現，請先確認注入器本身的 UNC 分數（見下一節）。

REQUIREMENTS系統需求

IRUKA 需要高 UNC / SUNC 分數的注入器。UNC（Unified Naming Convention）與 SUNC 是衡量注入器 API 覆蓋率的測試套件，分數代表該注入器實作了多少 Roblox 客戶端 API。

腳本具體需要下列能力：Highlight 實例、BillboardGui、Camera 屬性寫入、RemoteEvent 屬性寫入、以及 CFrame 直接寫入。缺少任何一項，對應的功能會靜默失效——不會報錯，只是沒有反應。

UNC 不足時會怎樣

腳本開頭會執行一次 UNC 檢測。分數不足時不會直接崩潰，而是降級：

環境行為
高 UNC / SUNC全功能解鎖，含 SilentAim 與 Auto Aim、七種 ESP 完整運作
低 UNC / SUNC基礎戰鬥可用，SilentAim 與 Auto Aim 不啟動，其餘功能照常
已知覆蓋不足的注入器 Solara、Xeno。這兩款在多數版本下無法完整支援 IRUKA 所需的 API，使用時會落到降級模式。

分數低不代表不能注入。注入本身通常會成功，只是執行到缺失的 API 時該功能不會生效。這也是為什麼腳本選擇降級而不是直接拒絕執行。

名稱實作關鍵參數

兩個容易誤解的依賴 第一，Ken ESP 與 Name ESP 共用同一個 BillboardGui。只開 Ken 時標籤尺寸為 160×15，只開 Name 時為 160×30，兩者都開時為 160×50。關掉 Ken 不會拆掉 Name 的標籤。
第二，Fruit ESP 不是獨立繪製，它把果實名稱插進 Name ESP 的同一行文字裡。因此 Name ESP 沒開時，Fruit ESP 不會有任何顯示。

Box ESP 的 V1 與 V2 互斥，同時開啟時只會有一個生效。

BRING MOB聚怪 Bring Mob

聚怪是 IRUKA 最常被討論的功能。它的作用是把附近怪物移動到玩家腳下，讓一次攻擊能同時命中大量目標。

項目值
有效半徑3000 studs
死區18 studs（比這更近的不拉，避免抖動）
執行頻率20Hz（每秒 20 次）
實作方式修改本機的網路模擬半徑，讓客戶端把遠處物件視為本地擁有
距離比較使用平方距離，不開根號，降低每幀運算量
擁有者檢查只對非本地擁有的物件操作

為什麼要限制在 20Hz

每一幀都對數千個物件做距離比較會嚴重拖慢客戶端。20Hz 是在「看起來連續」與「不影響幀率」之間取的平衡點。平方距離比較同樣是為了省掉每幀數千次的開根號。

18 studs 死區的作用

已經貼在身上的怪物如果繼續被拉，會出現來回抖動與穿模。死區讓它們停在原地不動。

聚怪的邊界 聚怪只影響你這一台電腦看到的狀態。它不會改變伺服器上的怪物位置，也不會影響其他玩家看到的畫面。這也是為什麼聚怪的效果在錄影裡明顯，但對其他玩家不可見。

COMBAT戰鬥機制

雙重距離判定

攻擊判定同時計算 3D 直線距離與 2D 平面距離（忽略高度差），任一在 400 studs 內即視為命中。加入 2D 判定是因為 Blox Fruits 的怪物常出現在高低差大的地形上，只看 3D 距離會漏掉正上方或正下方的目標。

六路流轉

腳本內部有一個 1 到 6 循環的計數器，每次攻擊依序切換路線。其中第 4 路會額外觸發一次命中。這個設計的目的不是提高傷害，而是讓攻擊的「形狀」不固定——連續攻擊若每次都走完全相同的路徑，容易被行為模式偵測辨識。六路流轉讓每次出手的間隔與路徑組合都不同。

攻擊延遲

腳本本身不插入額外的等待。實際出手間隔仍受遊戲端的遠端事件冷卻限制，腳本無法突破這個限制，只是不主動增加延遲。

ENGINESuccubus VM

IRUKA 的原始碼不是以明文 Lua 發佈，而是先編譯成自訂位元碼，再由 Succubus 產生一支自帶直譯器的腳本。Succubus 是厭璃自行開發的 Lua 混淆器，當前版本 v15.12。

編譯管線

從原始碼到最終產物經過六個實際執行的階段：

階段作用
LEXER字元流轉為 token
PARSERtoken 轉為語法樹（AST）
FLATTEN把巢狀控制流攤平成單層狀態機
BYTECODEAST 轉為自訂位元碼，此後 AST 被丟棄
STR_ENC字串進入加密盒，使用時才解出
VMGEN產生帶直譯器的最終 Lua 檔

每一份建置都不一樣

同一份原始碼每次編譯都會重新抽取下列元素：

項目數量 / 做法
自訂 opcode50 個，指令集版本 ISA v1.3
Runtime 識別符172 個，每份建置重新命名
字串盒方案4 種，取用時解碼、用完清除
Wire 佈局3 種，每份建置隨機抽一種
體積膨脹約 10.3 倍（原始 33KB → 產物 346KB）

結果是：針對某一份交付物寫的破解腳本，無法套用到下一份。因為 opcode 數值、分派鍵、密碼形狀、識別符名稱都不同。

使用時物化

位元碼不以明文陣列存在於記憶體中，而是在每條指令被執行前才即時組出來。因此「載入後傾印記憶體」拿到的不是一份可讀的程式，而是一堆已經被用過的中間值。

混淆能做到什麼、不能做到什麼 混淆不能阻止有權限的人 hook 你的環境。它能做的是讓 hook 到的東西失去意義——看到的是加密後的位元碼與隨機化的識別符，而不是可讀的邏輯。

LIMITS行為與限制

這一節列的是 IRUKA 做不到的事，以及容易被誤解的地方。

  • 不修改伺服器狀態。所有效果只存在於執行腳本的客戶端。其他玩家看不到你的聚怪、ESP 或改寫後的命中判定。
  • 無法突破遊戲端冷卻。攻擊間隔受遠端事件限制，腳本只是不額外加延遲。
  • 低 UNC 環境會缺功能。SilentAim 與 Auto Aim 在降級模式下不啟動，這是設計而非故障。
  • 手機注入器多數不適用。行動端的注入器普遍 UNC 覆蓋不足，會落到降級模式。
  • ESP 有依賴關係。Fruit ESP 需要 Name ESP 開著；Ken 與 Name 共用同一個標籤。
  • 聚怪有死區。18 studs 內的怪物不會被拉動。

FAQ常見問題

IRUKA 是免費的嗎？

是，完全免費。沒有付費牆、沒有訂閱、不需要金鑰（key）。所有功能對所有使用者開放，沒有「免費版 / 付費版」的區分。

海豚跟 IRUKA 是同一個東西嗎？

是。IRUKA 是英文名，海豚是中文名，指同一支腳本。全名寫作 IRUKA 海豚，由團隊厭璃（YanLi / YLI）開發。

IRUKA 需要什麼注入器？

需要高 UNC / SUNC 分數的注入器。已知 Solara 與 Xeno 覆蓋不足。UNC 不足時腳本仍可注入，但會自動降級：SilentAim 與 Auto Aim 不啟動，其餘功能照常。

為什麼我執行了但沒反應？

最常見的三個原因：注入器 UNC 不足（落到降級模式）、腳本版本過舊（loadstring 需要從 Discord 取最新版）、或遊戲本身剛更新導致 API 位移。先確認注入器的 UNC 分數，再確認 loadstring 是不是當前版本。

IRUKA 會不會導致帳號被封鎖？

任何 Roblox 腳本都違反 Roblox 服務條款，使用本身存在帳號風險。IRUKA 能降低的是被其他玩家檢舉與被行為模式偵測的機率，無法保證帳號安全。六路流轉與每份建置重新隨機化都是為此設計，但沒有任何腳本能提供保證。

聚怪（Bring Mob）是什麼？

把 3000 studs 內的怪物拉到玩家腳下，方便一次擊殺。實作方式是修改本機的網路模擬半徑，以 20Hz 節流執行，18 studs 內不拉以避免抖動。只影響你自己的畫面。

400 studs 的攻擊距離是真的嗎？

400 studs 是判定模組的距離參數上限。腳本用 3D 直線距離與 2D 平面距離雙重判定，任一落在範圍內即視為命中。實際生效的距離仍取決於你當前的角色狀態與果實條件——腳本不會改變你的外觀或體型，也不會憑空擴大攻擊範圍。

需要金鑰（key）嗎？

不需要。IRUKA 沒有 key 系統，也沒有每日驗證。

怎麼更新？

回到 Discord 群組取得當前的 loadstring，重新執行即可。舊的 loadstring 在版本更新後可能失效。

Succubus 是什麼？

厭璃自行開發的 Lua 混淆器，當前版本 v15.12。它把 Lua 編譯成自訂位元碼，再產生一支自帶直譯器的腳本，並在每份建置重新隨機化 opcode 數值、識別符名稱與加密參數。IRUKA 就是用 Succubus 混淆後發佈的。

支援手機嗎？

不建議。行動端注入器的 UNC 覆蓋普遍不足，會落到降級模式，失去 SilentAim 與 Auto Aim。IRUKA 的設計前提是桌面端的高 UNC 環境。

ESP 可以同時全開嗎？

大部分可以。但有兩個例外：Box ESP V1 與 V2 互斥，同時開啟只會有一個生效；Fruit ESP 需要 Name ESP 開著才有顯示。

會不會被其他玩家看到我在用？

ESP、聚怪、改寫後的命中判定都只存在於你的客戶端，其他玩家看不到。但你的角色行為（例如攻擊距離異常、移動模式）仍然可能被觀察到，這是任何客戶端腳本都無法完全隱藏的部分。

原始碼可以取得嗎？

不行。發佈的是 Succubus 混淆後的產物，不含可讀的原始碼。

GLOSSARY術語表

掛佛
泛指使用外掛配合佛果（Buddha）進行 HVH 的玩家。是身份詞，不是貶義詞。帶貶義的稱呼是 skid。
HVH
Hunter vs Hunter。Blox Fruits 中玩家之間互相狩獵的對戰形式，與 PVE 刷怪相對。
佛果 / Buddha
Blox Fruits 的一種惡魔果實，變身後體型與攻擊範圍大幅增加。掛佛流派的核心。
farm / pvp
腳本的兩大分類。farm 指向刷怪、刷素材；pvp 指向玩家對戰。IRUKA 屬於後者。
UNC / SUNC
Unified Naming Convention / SUNC。衡量注入器實作多少 Roblox 客戶端 API 的測試套件。分數越高，能執行的腳本越多。
Executor（注入器）
把 Lua 腳本注入 Roblox 客戶端的第三方程式。常見的有 Wave、Delta、Solara、Xeno 等。
Bring Mob（聚怪）
把周圍怪物移動到玩家身邊的功能。原理是修改本機的網路模擬半徑。
ESP
Extra Sensory Perception。在畫面上顯示其他玩家或怪物的位置、血量、名稱等資訊。
SilentAim
命中判定轉向目標，但畫面不顯示轉動。與 Auto Aim 的差別在於視覺回饋。
VM（虛擬機器）
混淆技術的一種：把原始碼編譯成自訂位元碼，附上一支直譯器一起發佈。逆向者看到的是位元碼而非原始邏輯。
Opcode
位元碼指令的編號。Succubus 使用 50 個自訂 opcode，且每份建置重新對應數值。
AST（語法樹）
Abstract Syntax Tree。原始碼解析後的結構化表示。Succubus 在轉為位元碼後就丟棄 AST。
studs
Roblox 的長度單位。一個 stud 大約等於一個標準角色的半身寬。
Loadstring
Lua 的動態執行函式。腳本發佈時通常給一行 loadstring 指令，貼進注入器即可執行。

DIFFERENCES與同類腳本的差異

這一節只描述 IRUKA 的做法，不評價特定產品。多數同類腳本在下列幾個地方選擇不同路線：

面向IRUKA 的做法常見做法
混淆自研 VM，每份建置重新隨機化使用現成混淆器，或直接發佈明文
價格完全免費，無 key免費層 + 付費層，或 key 驗證
低 UNC 處理偵測後降級，其餘功能照常直接報錯或靜默失效
ESP 依賴明確標示共用與依賴關係通常不說明
聚怪節流20Hz + 平方距離 + 死區逐幀執行，較耗效能

這些差異不代表其他做法是錯的，只是取捨不同。免費且無 key 意味著沒有收入支撐，更新頻率取決於開發者意願；自研 VM 意味著每次改版都要重新驗證管線。
